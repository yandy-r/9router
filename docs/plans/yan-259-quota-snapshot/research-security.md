# Security Review — YAN-259 Quota Snapshot Service (Phase 1 of YAN-258)

Scope: new in-memory quota snapshot store, passive header ingestion at the post-response hook,
active poller (USAGE_HANDLERS reuse), Claude `/api/oauth/profile` plan-tier probe, persisted
`planTier`, visibility via `/api/usage/[connectionId]`. Read-only review of the design against the
current worktree (`9router-feat-yan-259-quota-snapshot`).

## Executive Summary

No CRITICAL issues if the feature follows existing patterns. The riskiest new surfaces are:
(1) trusting upstream header values into routing inputs — must validate/clamp every number and cap
collection sizes; (2) an unbounded `Map<connectionId|model, …>` cache family (precedent in
`src/sse/services/antigravityQuota.js` already leaks entries for deleted connections);
(3) Claude OAuth profile/usage probes carrying tokens to undocumented endpoints — ban/lockout risk
is mitigated by existing 5-min cache + 3-min 429 cooldown (`open-sse/services/usage/claude.js:19,24`)
and must not be bypassed by the new poller; (4) auth on the visibility route is the dashboard-wide
deny-by-default proxy, which weakens to "anyone on the network" when `requireLogin=false`. The
`ENABLE_REQUEST_LOGS=true` debug logger writes full headers (including `Authorization`) to disk —
pre-existing, but the new hook must not add token/header logging on top.

## Authentication and Authorization

- New outbound calls use existing per-connection OAuth tokens via `proxyAwareFetch` — correct channel (respects per-connection proxy/relay config, `open-sse/utils/proxyFetch.js`). No new credential storage needed; planTier is derived state, not a credential.
- Visibility: `/api/usage/[connectionId]` is reached only through `src/proxy.js` → `dashboardGuard.js`. Deny-by-default for `/api/*`; JWT cookie (`auth_token`, `src/lib/auth/dashboardSession.js`) or CLI token (`x-9r-cli-token`) required. `ALWAYS_PROTECTED`/`LOCAL_ONLY_PATHS` lists do not cover `/api/usage` — acceptable since it spawns no processes, but `?force=1` performs upstream calls, so it is not purely read-only (see A2).
- No role model exists; any authenticated dashboard session can force-probe any connection.

## Data Protection

- At rest: planTier lands in `providerSpecificData` inside the SQLite DB at `DATA_DIR`/`~/.9router` (`src/lib/db/paths.js`). Same protection level as tokens (DB file, no field-level encryption observed). planTier alone is low sensitivity — acceptable.
- In transit: profile/usage probes go to first-party provider hosts from the registry (`U("claude").oauthUrl`, `open-sse/services/usage/claude.js:10-15`) over HTTPS; per-connection proxy/relay config applies. Do not send tokens to any non-registry URL derived from upstream data (SSRF-by-upstream) — only registry constants.
- In logs: see W4. Feature logs must be metadata-only (provider, connectionId prefix, clamped values).
- Export/sync: full-DB export (password-gated) and optional cloud sync carry `providerSpecificData` wholesale (W5).

## Dependency Security

- No new dependencies required by the design (stdlib `Map`, `fetch` via existing `proxyAwareFetch`) — consistent with project rules. Nothing to audit.

## Input Validation

- Trust boundaries: (a) upstream response headers, (b) upstream probe JSON, (c) `?force=1` query param (d) model ids from upstream quota payloads used as map keys.
- Required at ingest (per W2): finite-number coercion via existing `toFiniteNumber` (`open-sse/services/usage/shared.js:45`), clamp to `[0,1]` after scale normalization (0–1 vs 0–100 runtime detection must be per-window, not sticky per connection, since Anthropic headers and probe disagree), reset-time sanity window, cap on windows-per-connection and per-kind cardinality.
- Reject-and-keep-previous is the specified failure mode — correct; do not persist partial parse results.
- `force` param: existing `=== "1"` string check is fine.

## Infrastructure Security

- Gateway binds localhost by default; tunnel exposure is opt-in and dashboard-auth-gated (`dashboardGuard.js:212-254`). Snapshot data adds no new listener.
- Probe endpoints are undocumented and versioned (`anthropic-beta: oauth-2025-04-20`) — pin the beta header as the existing code does; treat 404/403 as "feature unavailable", not retryable error.
- Per-connection proxy configs (`connectionProxyUrl`) mean OAuth tokens may transit user-configured proxies — pre-existing; the profile probe must go through `proxyAwareFetch` with the connection's proxyOptions, never bare `fetch`.

## Secure Coding Guidelines (for the implementation)

1. One post-response hook; parsers in `open-sse/config/` return `{ kind, usedFraction, resetsAt }` or null — never throw (matches RTK fail-open convention, `open-sse/AGENTS.md`).
2. All numbers through a single `clamp01(toFiniteNumber(v))`; all reset times through one sane-window parser. Reuse `open-sse/services/usage/shared.js` helpers.
3. Snapshot store: `Map` keyed by connectionId; windows as `Map` or null-prototype object; per-connection cap ~50 windows; TTL eviction on read; purge on connection delete.
4. No token-keyed caches in new code (precedent in `claude.js` is not to be copied); key by connectionId.
5. Log lines: provider + `connectionId.slice(0,8)` + clamped values only. No headers, no tokens, no raw upstream payloads at info/warn.
6. Profile probe: registry URL only, `user:profile`-scoped tokens only, 403 → cached "unknown" with TTL, success → persist only `rate_limit_tier` string into `providerSpecificData.planTier` via the existing merge pattern (`route.js:91-103`) so other keys survive.
7. Poller: honor existing 5-min cache / 3-min 429 cooldown; dedup in-flight; jitter per-connection schedule; never set `force`.

## Trade-off Recommendations

- **Persist planTier (low value) vs. probe cost (ban risk):** persist once and refetch on 24h TTL / token refresh — do not re-probe on every dashboard view. The weight table degrades gracefully to `1`.
- **`model:<id>` windows:** keep, but cap cardinality; model-scoped windows are the main accuracy win for Claude Opus/Sonnet splits.
- **Visibility via existing route vs. new route:** extend `/api/usage/[connectionId]` response with a `snapshot` field (no new auth surface) rather than adding a route — but strip `force` influence on the snapshot fields.
- **Fail-open everywhere:** unknown tier/malformed header → base weight, debug log. Already the spec; enforce in review.
