# YAN-259 Practices Research — Reuse, Modularity, KISS

## Executive Summary

The repo already contains ~80% of what YAN-259 needs as working, tested patterns: a per-token dedup+TTL cache with stale-on-failure (`usage/claude.js`), a strike-breaker in-memory quota cache with error-path refresh (`src/sse/services/antigravityQuota.js`), a global-singleton background scheduler with per-provider config and deps injection (`src/shared/services/quotaAutoPing.js`), generic `x-ratelimit-*` header→quota parsing (`usage/groq.js`), and a normalized quota shape (`{used,total,remainingPercentage,resetAt}`) that every `USAGE_HANDLERS` fetcher already emits. No existing code parses the Claude `anthropic-ratelimit-unified-*` or Codex `x-codex-*` passive headers — that is genuinely new code, but it is four small parser functions, not a framework. KISS verdict: one new module (`quotaSnapshot.js`) + one config file (`planCapacity.js`) + one parser map, folding `antigravityQuota.js` onto the new store instead of building a second cache. Anything beyond that (class hierarchies, DI containers, per-provider subclasses) would violate the repo's plain-function, config-driven convention.

## Abstraction vs. Repetition

- **Abstract once**: `toUsedFraction` clamp+scale helper (used by every parser), `parseResetTime` (already exists — reuse, don't wrap), window-expiry check (`resetsAt <= now ⇒ drop`).
- **Accept repetition**: the 4 header parsers share shape (get header → number → window) but differ in header names, scales, reset semantics (epoch vs RFC3339 vs duration string vs window-minutes classification). A generic "header spec DSL" config would be more lines than the parsers themselves and harder to test. Keep them as separate small functions; the shared helpers (parseResetTime, toFiniteNumber, Groq's duration parser — consider exporting `parseGroqDurationMs` from a shared spot if both Codex reset-after-seconds and OpenAI `6m0s` need it) kill the real duplication.
- **Do NOT duplicate**: antigravity quota cache (must fold, per issue spec line 12), Claude 429-cooldown state (poller must call `getClaudeUsage` which already enforces cooldown internally — do not add a second cooldown), proxy option building (`buildProxyOptions` in quotaAutoPing.js:101-109 is duplicated in antigravityQuota.js:110-117 — third copy in the new poller would be one too many; this is the one extraction worth doing: move to a shared helper or import).

## Interface Design

Minimal surface, plain functions (repo has no DI framework; tests inject `deps` objects):

```
// open-sse/services/quotaSnapshot.js
ingestQuotaHeaders(provider, connectionId, model, headers)  // fail-open void
ingestUsageResult(connectionId, usageResult)                 // fail-open void
getQuotaSnapshot(connectionId) → {windows[], planTier, updatedAt} | null
computeEffectiveWeight({manualWeight, planTier, provider, snapshot, model, floor=0.05}) → number  // pure
```

```
// open-sse/config/quotaHeaderParsers.js
QUOTA_HEADER_PARSERS = { claude: fn, codex: fn, groq: fn, "anthropic-api": fn, ... }
// each: (Headers) → [{kind, usedFraction, resetsAt, source:"header"}] | []
```

Design rules matching repo norms:

- Fail-open: every ingest entry wraps parse in try/catch, logs `debug`, never throws (RTK/rtk convention, chatCore savers precedent).
- Unknown data ⇒ base × 1 in `computeEffectiveWeight`; never `NaN` out (validate `Number.isFinite` at ingest, clamp `[0,1]` — acceptance criterion).
- Return `null` (not `{}`) for missing snapshot — matches `antigravityQuota.js` returning `null` on failure and `getUsageForProvider` returning `{message}` for unsupported.
- Window `kind` taxonomy from issue: `"5h"|"7d"|"day"|"month"|"model:<id>"` — string tag, no enum module needed (5 values).
- Poller mirrors `runQuotaAutoPingTick(deps, state)` signature so existing test style (inject fake deps/state, no module mocking) carries over.

## Testability Patterns

Existing patterns to copy (all in `tests/unit/`):

- **Pure-function tests**: header parsers are pure `(Headers) → windows[]` — construct `new Headers({...})` directly, no mocks. Precedent: `tests/unit/groq-usage.test.js:25-30` builds exactly these header sets.
- **DI tick tests**: poller takes `(deps, state)` — inject fake `getProviderConnections/getUsageForProvider/updateProviderConnection` and a fresh state object; assert cadence gating and cooldown by advancing injected `Date.now`. Precedent: `quotaAutoPing.js:286` shape; codex reset-credits tests (`tests/unit/codex-reset-credits.test.js`) use `vi.mock` but DI is cleaner — follow quotaAutoPing's existing test suite.
- **Cache behavior tests**: antigravity tests (`antigravity-quota-routing.test.js`, `antigravity-weekly-quota.test.js`) must stay green through the fold — they exercise cache semantics via `auth.js` + `handleAntigravityQuotaError`; keep those exported functions as the stable API during refactor.
- **Expiry tests**: snapshot expiry at `resetsAt` — pass a snapshot with past `resetsAt` into the read path; no timers needed if the expiry check is a pure predicate.
- Regression gate: `tests/__baseline__/verify-no-regression.mjs` after adding tests (known-fails semantics, not all-green).

## Build vs. Depend

Build everything. Zero new dependencies:

- Header access: Web-standard `Headers` object from `proxyAwareFetch`/undici — stdlib.
- Scheduling: `setInterval` (stdlib) — precedent quotaAutoPing.js:323.
- Reset-time parsing: `parseResetTime` + Groq duration regex already in-repo.
- No zod/validation lib: repo validates by `typeof`/`Number.isFinite` inline everywhere (see `toFiniteNumber`, `hasUtilization`); adding a schema lib would be the repo's first.
- No lru-cache/ttl lib: three in-repo hand-rolled caches (claude usage, antigravity, autoPing resetCache) establish the Map-based pattern.
